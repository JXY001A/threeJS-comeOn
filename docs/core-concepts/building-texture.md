## 什么是 PBR 贴图

PBR（Physically Based Rendering，基于物理的渲染）不依赖单一颜色，而是通过**多张贴图**分别控制材质的各个物理属性，组合起来模拟真实世界的外观。

Demo 中砖墙建筑使用了三张贴图：

| 贴图类型 | 文件 | 格式 | 加载器 | 作用 |
|---------|------|------|--------|------|
| 颜色贴图（map） | `square_brick_floor_diff_4k.jpg` | JPG | `TextureLoader` | 物体的基础颜色/反照率，决定"这个表面是什么花纹" |
| 法线贴图（normalMap） | `square_brick_floor_nor_gl_4k.exr` | EXR | `EXRLoader` | 模拟表面凹凸细节，在不增加几何面数的前提下让表面看起来有立体感 |
| 粗糙度贴图（roughnessMap） | `square_brick_floor_rough_4k.exr` | EXR | `EXRLoader` | 逐像素控制表面光滑程度，砖缝粗糙、砖面光滑 |

> 另外还有一张 `square_brick_floor_disp_4k.png`（置换贴图），在需要真实改变几何体顶点时使用，本例未用到。

## 贴图加载的核心规则

### 1. 格式决定加载器

| 加载器 | 支持格式 | 典型用途 |
|--------|---------|---------|
| `TextureLoader` | JPG、PNG、BMP、GIF | 颜色贴图、不透明度贴图 |
| `EXRLoader` | EXR（OpenEXR） | 法线贴图、粗糙度贴图、金属度贴图、HDR 环境贴图 |
| `RGBELoader` | HDR（Radiance RGBE） | HDR 环境贴图 |

> **踩坑提醒**：用 `TextureLoader` 加载 `.exr` 会静默失败，贴图不显示且不报错。

### 2. colorSpace 必须对

Three.js 使用线性工作流进行光照计算，不同类型贴图的色彩空间处理不同：

| 贴图类型 | colorSpace 设置 | 原因 |
|---------|----------------|------|
| `map`（颜色贴图） | `SRGBColorSpace` ✅ | JPG/PNG 存储的是 sRGB 编码颜色，需要标记让 GPU 做 gamma → linear 转换 |
| `normalMap`（法线贴图） | 不设（默认 Linear） ✅ | 存储的是方向向量数据，不是颜色，gamma 校正会破坏数据精度 |
| `roughnessMap`（粗糙度贴图） | 不设（默认 Linear） ✅ | 存储的是物理参数数据，必须保持线性 |
| `metalnessMap`（金属度贴图） | 不设（默认 Linear） ✅ | 同上 |

### 3. 静态资源路径

```ts
// ❌ 本地绝对路径，浏览器无法访问
'/Users/xxx/project/textures/brick.jpg'

// ❌ 相对路径，打包后路径解析可能出错
'../textures/brick.jpg'

// ✅ 放在 public/ 目录，使用绝对根路径
// public/textures/brick.jpg → 运行时访问 /textures/brick.jpg
'/textures/brick.jpg'
```

## PBR 材质的关键参数

### metalness（金属度）

| 值 | 表现 | 适用材质 |
|----|------|---------|
| 0 | 100% 漫反射，非金属（电介质） | 砖墙、木头、塑料、布料 |
| 0.1~0.3 | 略带金属光泽 | 砖墙（含微量金属矿物） |
| 0.5~0.8 | 明显金属质感 | 生锈金属、合金 |
| 1.0 | 100% 镜面反射，纯金属 | 抛光金/银/铜 |

> **关键踩坑**：`metalness > 0.5` 时，大部分表面颜色来自环境反射。
> 如果没有设置 `envMap`（环境贴图），金属表面会**一片漆黑**！
> 本 Demo 设为 0.1 正是这个原因。

### roughness（粗糙度）

| 值 | 表现 |
|----|------|
| 0 | 镜面般光滑 |
| 0.5 | 中等粗糙 |
| 1.0 | 完全粗糙，漫反射主导 |

使用 `roughnessMap` 时，基础 `roughness` 值设为 1.0，让贴图完全接管——贴图像素值会与基础值相乘得到最终粗糙度。

## 贴图重复与包裹

```ts
// wrapS/wrapT 控制 UV 坐标超出 [0,1] 范围时的行为
texture.wrapS = THREE.RepeatWrapping  // 水平重复
texture.wrapT = THREE.RepeatWrapping  // 垂直重复

// repeat 控制贴图在表面上重复的次数
texture.repeat.set(2, 2)  // 水平和垂直各重复 2 次
```

Demo 中 `repeat.set(width / 2, height / 2)` 让贴图随建筑尺寸自适应缩放，避免贴图被拉伸变形。

## 贴图是如何“贴”到几何体上的？——UV 映射原理

### 核心概念：UV 坐标

一张 2D 图片要包裹在 3D 物体上，需要一个**映射关系**——把图片上的每个点（像素）与几何体表面上的每个点（顶点）对应起来。这个映射靠 **UV 坐标** 完成。

```
 图片空间（2D，像素）                    网格表面（3D，顶点）
┌─────────────────────┐                 ┌─────────────┐
│ (0,1)         (1,1) │                 │  A ─── B    │
│                     │    UV 映射       │  │     │    │
│   🧱 砖墙贴图 🧱    │  ◀─────────▶    │  │     │    │
│                     │                 │  C ─── D    │
│ (0,0)         (1,0) │                 └─────────────┘
└─────────────────────┘

A: (x,y,z) ← UV (0, 1)
B: (x,y,z) ← UV (1, 1)
C: (x,y,z) ← UV (0, 0)
D: (x,y,z) ← UV (1, 0)
```

**每个几何体顶点除了有 (x, y, z) 位置信息，还附带一个 (u, v) 纹理坐标**：

- **u**：水平方向，0 = 图片最左边，1 = 图片最右边
- **v**：垂直方向，0 = 图片最下边，1 = 图片最上边

Three.js 内置的基础几何体（`BoxGeometry`、`PlaneGeometry` 等）已经自动生成了 UV 坐标，你只需提供贴图即可。

### BoxGeometry 的 UV 分布

一个立方体有 6 个面，`BoxGeometry` 把每个面都映射到一张完整的贴图上：

```
     ┌─────────┐
     │   Top   │
     │  (顶面)  │
┌────┼────┬────┼────┬────┐
│Left│ Fr │ Ri  │ Ba │
│ 左 │  前 │ 右  │ 后 │
└────┴────┴─────┴────┴────┘
     │  Bot   │
     │  (底面) │
     └────────┘
```

默认情况下，**每个面独立占用整张贴图**。也就是说，给 `BoxGeometry` 一张砖墙贴图，它的 6 个面都会铺满同一张砖墙图案。

> 这就是为什么 Demo 中的每栋建筑看起来是“通体砖墙”——不是设计，而是 BoxGeometry 默认 UV 行为。

### GPU 如何计算“贴图上的哪一点”画到“屏幕上的哪一像素”？

这是你问题的核心——**窗户贴图的位置不是手动指定的，而是数学计算出来的**。整个过程分两步：

#### 第一步：顶点 → 三角形 → 像素（光栅化）

BoxGeometry 的前面由两个三角形组成，每个顶点都有固定的 UV：

```
    前面（BoxGeometry 自动生成）

  A(UV:0,1) ●────────● B(UV:1,1)
            │╲       │
            │  ╲     │
            │    ╲   │
            │      ╲ │
  C(UV:0,0) ●────────● D(UV:1,0)

  三角形1: A-B-C（左上三角）
  三角形2: B-D-C（右下三角）
```

每个顶点的 UV 是 Three.js 在创建 `BoxGeometry` 时写死的：
- 左上角 A `→ (u=0, v=1)` 对应贴图的左上角
- 右上角 B `→ (u=1, v=1)` 对应贴图的右上角
- 左下角 C `→ (u=0, v=0)` 对应贴图的左下角
- 右下角 D `→ (u=1, v=0)` 对应贴图的右下角

#### 第二步：三角形内部怎么办？——GPU 的线性插值

四个角定了，但三角形内部有成千上万个像素，这些像素的 UV 怎么算？

**GPU 自动做线性插值（Linear Interpolation）**，公式很简单：

```
对于三角形内部任意一点 P：
  u(P) = wA·uA + wB·uB + wC·uC
  v(P) = wA·vA + wB·vB + wC·vC

其中 wA、wB、wC 是 P 到三个顶点的“重心坐标”（权重之和 = 1）
```

**用建筑墙面 + 窗户贴图举例**（假设贴图是一张 1000×1000 的图片，窗户在贴图正中间）：

```
        贴图（1000×1000 像素）
  (u=0, v=1)            (u=1, v=1)
     ┌──────────────────────┐
     │  🧱🧱🧱🧱🧱🧱🧱🧱🧱  │  ← 贴图顶部是砖墙
     │  🧱🧱🧱🧱🧱🧱🧱🧱🧱  │
     │  🧱🧱  ┌────┐ 🧱🧱  │  ← 窗户在该区域
     │  🧱🧱  │  🪟 │ 🧱🧱  │     u∈[0.3, 0.7]
     │  🧱🧱  └────┘ 🧱🧱  │     v∈[0.3, 0.7]
     │  🧱🧱🧱🧱🧱🧱🧱🧱🧱  │
     │  🧱🧱🧱🧱🧱🧱🧱🧱🧱  │
     └──────────────────────┘
  (u=0, v=0)            (u=1, v=0)
```

对应的几何体前面（假设宽 4、高 10，窗户在中间偏上）：

```
        几何体前面（宽 4m × 高 10m）
  (u=0, v=1)            (u=1, v=1)
     ●────────────────────●
     │ 砖墙区域 砖墙区域 │  ← 贴图的顶部被拉到这里
     │ 砖墙区域 砖墙区域 │
     │ ───── 窗户区域 ───│  ← 贴图中间(0.3~0.7) 被拉到这里
     │ 砖墙区域 砖墙区域 │
     │ 砖墙区域 砖墙区域 │
     ●────────────────────●
  (u=0, v=0)            (u=1, v=0)
```

**关键点**：
- 几何体尺寸是 4m×10m，但 UV 空间永远是 0→1
- 贴图尺寸是 1000×1000px，但 UV 空间也永远是 0→1
- **UV 坐标是与尺寸无关的比例值**——无论物体多大、贴图分辨率多高，u∈[0.3,0.7] 永远对应“中间 40%”的区域

#### 窗户位置是怎么“计算”出来的

以窗户在建筑前面正中间偏上为例：

```
窗户在几何体上的实际位置：
  水平：X ∈ [-0.8, 0.8]（占前面宽度的 40%）
  垂直：Y ∈ [3.5, 6.5]（占前面高度的 30%）

GPU 计算这个位置对应的 UV：
  对于窗户区域的任意一个像素 P(x, y)：
    u(P) = (x + 2) / 4    → x ∈ [-0.8, 0.8] 映射到 u ∈ [0.3, 0.7]
    v(P) = (y + 0) / 10   → y ∈ [3.5, 6.5] 映射到 v ∈ [0.35, 0.65]

贴图中这个 UV 范围恰好是窗户图案 → 窗户就出现在建筑的窗户位置
```

**这不是 Three.js 或 JS 代码在算**——这是 GPU 在光栅化阶段，对每个像素自动执行的硬件级插值运算。你只需要做两件事：

1. 准备一张正确布局的贴图（窗户画在贴图的中间偏上位置）
2. 确保几何体顶点的 UV 是标准 0→1 映射（BoxGeometry 默认就是）

GPU 会自动完成剩下的一切。

### 如果建筑物有窗户、门怎么办？

现实中的建筑不是纯砖墙——它有窗户、门、阳台。在 3D 中实现这种效果有三种主流方案。

#### 方案一：材质数组（最简单，推荐入门）

`BoxGeometry` 支持为不同面设置不同材质：

```ts
// 6 个材质，分别对应：右、左、上、下、前、后
const materials = [
  // 右面 — 带窗户的墙面贴图
  new THREE.MeshStandardMaterial({ map: wallWithWindowTex }),
  // 左面 — 纯砖墙贴图
  new THREE.MeshStandardMaterial({ map: brickTex }),
  // 顶面 — 屋顶材质（纯色）
  new THREE.MeshStandardMaterial({ color: 0x444444 }),
  // 底面 — 不需要贴图
  new THREE.MeshStandardMaterial({ color: 0x666666 }),
  // 前面 — 带门 + 窗户的墙面
  new THREE.MeshStandardMaterial({ map: wallWithDoorTex }),
  // 后面 — 纯砖墙
  new THREE.MeshStandardMaterial({ map: brickTex }),
]

const building = new THREE.Mesh(geometry, materials)
```

优点：简单直接，只需要准备对应的贴图图片。

缺点：每个面独立贴图，最终贴图数量 = 建筑面数 × 贴图类型数，资源管理复杂。

#### 方案二：贴图图集（Texture Atlas，工业标准）

把一栋建筑的所有表面贴图**拼到一张大图上**，通过精确调整 UV 坐标来裁剪：

```
   贴图图集（一张图包含所有表面）
┌──────────────┬──────────────┐
│              │              │
│   前面（门）  │  左面（窗户）  │
│   UV:(0,0)   │   UV:(0.5,0) │
│   →(0.5,0.5) │   →(1,0.5)   │
│              │              │
├──────────────┼──────────────┤
│              │              │
│   右面（窗户） │  后面（墙）   │
│   UV:(0,0.5) │   UV:(0.5,0.5)│
│   →(0.5,1)   │   →(1,1)      │
│              │              │
└──────────────┴──────────────┘
```

然后用代码控制每个面的 UV 偏移：

```ts
// 对前面的 4 个顶点设置 UV 为 (0, 0) → (0.5, 0.5)
// 这就是标准 3D 建模软件（Blender/Maya）导出模型时的做法
```

优点：一次加载一张图，GPU 友好，性能最优。

缺点：需要在建模软件中做 UV 展开，或手动计算 UV 偏移（Three.js 内置几何体的 UV 无法直接偏移，需要用自定义几何体）。

#### 方案三：几何体拼接（最灵活）

不在一张贴图上做文章，而是**用独立几何体拼出窗户和门**：

```ts
// 主体建筑（砖墙）
const wallGeo = new THREE.BoxGeometry(4, 10, 4)
const wall = new THREE.Mesh(wallGeo, brickMaterial)

// 窗户（深色小方块，略微凸出）
const windowGeo = new THREE.BoxGeometry(1.2, 1.5, 0.1)
const window = new THREE.Mesh(windowGeo, windowMaterial)
window.position.set(0, 2, 2.01) // 放在前墙表面
wall.add(window)  // 作为子对象贴在墙上

// 门
const doorGeo = new THREE.BoxGeometry(1, 2.5, 0.1)
const door = new THREE.Mesh(doorGeo, doorMaterial)
door.position.set(1.5, 0, 2.01)
wall.add(door)
```

优点：不需要额外贴图，纯代码控制，可单独交互（点击开门等）。

缺点：增加了几何体数量，复杂建筑会变得很臃肿。

### 三种方案对比

| 方案 | 贴图数量 | 几何体数量 | 灵活性 | 适用场景 |
|------|---------|-----------|--------|---------|
| 材质数组 | 多张 | 1 个 Box | 中 | 简单建筑，每个面都不一样的快速原型 |
| 贴图图集 | 1 张 | 1 个 Box | 低（但效果最好） | 游戏资产、需要高性能 |
| 几何体拼接 | 0~几张 | 多个 | 高 | 需要交互的建筑、精细场景 |

> 你的城市一角 Demo 可以先用方案三——把窗户做成深色小 Box 贴在建筑上，效果直观且容易理解。

## 源码对应关系

所有贴图相关的核心逻辑在 [index.tsx](../../building-texture/index.tsx) 的 `createBuilding` 函数中：

- **纹理加载** → `textureLoader.load()` / `exrLoader.load()`
- **包裹与重复** → `wrapS` / `wrapT` + `repeat.set()`
- **色彩空间** → `diffMap.colorSpace = SRGBColorSpace`（仅颜色贴图）
- **材质组装** → `MeshStandardMaterial({ map, normalMap, roughnessMap, metalness, roughness })`

其中 `metalness: 0.1` 是本 Demo 正常运行的关键——它避免了高金属度 + 无环境贴图导致的"黑屏"问题。
